# Documentation Style Guide

## Voice and tone
Use institutional, clear, implementation-aware, and non-promotional language.

## Terminology conventions
- Use terms from `/docs/reference/glossary.md` consistently.
- Introduce acronyms on first use.

## Heading and formatting conventions
- Use sentence-case headings.
- Keep sections scoped and avoid ambiguous requirements.
- Prefer tables for status/index material.

## Requirement language
Use RFC 2119 keywords:
- **MUST**: mandatory requirement.
- **SHOULD**: strong recommendation unless justified otherwise.
- **MAY**: optional behavior.

## Disclaimer guidance
Tokenomics and compliance-related docs MUST include disclaimers stating that pre-TGE points are not tokens and that outcomes are subject to legal/regulatory review.
